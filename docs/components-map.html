Why it's shaped this way

Code decides. No model votes.

Vaani reports what the caller said. Every gate that follows — service area, the five criteria, the pricing scan — is plain code reading a config file, so a persuasive caller cannot talk a model past a rule. Where the agent and the code disagree, the lead is flagged for a human rather than quietly resolved either way.

Record before notify. Always.

The row is written before anything is sent, and notification failures are caught and logged rather than raised. If email is down the enquiry still exists. The one case that returns an error is a failed write — the one case where a retry is what we want.

The number is never in the message.

A shared inbox is read by several people and forwarded without thought. The callback number lives on the record, behind the dashboard password, and a guard runs over every rendered card — subject, text and HTML — and refuses to send one that contains anything number-shaped, including a number the agent transcribed into a scope note.

A leaked price is an incident, not a metric.

It alerts the founder the moment it is written, independent of where the lead is routed, and the dashboard shows it in red with this must read zero. Trusting the agent's own answer would be the agent grading its own homework, so the transcript is scanned too.

"I don't know" is never treated as "no".

An unrecognised locality is escalated to a human, not declined. Declining on a bad phone line is how a Kothrud project gets turned away.
